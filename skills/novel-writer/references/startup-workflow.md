# Startup Workflow — 新小说立项与首卷准备

Use this when starting a new novel or materially re-establishing an old project.

Load `execution-modes.md` first. It owns confirmation semantics and mode behavior. This file owns startup order only; linked references own artifact content.

## Canonical order

1. Premise / seed confirmation
2. Style and element selection
3. Compatibility Check and Tone Lock
4. Length and chapter scale
5. Project Profile confirmation
6. Whole-book spine confirmation
7. System Bible confirmation
8. Current-volume and current-arc plan confirmation
9. Story Memory initialization when the project will persist
10. Current chapter/scene Preflight
11. Seven-stage prose delivery

Do not ask for final length before the style, element hierarchy, and Tone Lock are understood. Do not fully detail every future volume before writing the current one.

## 1. Premise / seed

Summarize and confirm:

- genre/domain;
- protagonist seed;
- central conflict;
- world direction;
- reader-facing appeal;
- disliked or forbidden tendencies;
- ending direction when the user already knows it.

Keep brainstorming outside authoritative project files until confirmed.

## 2. Style and elements

Use:

- `style-and-element-selection.md`;
- `style-library.md`;
- `element-library.md`;
- `style-element-compatibility.md`.

Select one main style, up to two supporting styles, a bounded core element hierarchy, forbidden tendencies, compatibility constraints, and Tone Lock.

## 3. Length and chapter scale

After compatibility is clear, define:

- target length range;
- approximate chapter count or chapter-size range;
- expected volume/arc structure;
- production cadence expectations;
- whether the selected complexity fits the scale.

When it does not fit, reduce core complexity or expand the scale. Do not compress every relationship, consequence, and payoff merely to preserve an early number.

## 4. Project Profile

Use `project-profile-workflow.md` to create the authoritative style, element, Tone Lock, reader promise, Style Anchors, and revision-boundary file.

Show the complete draft and obtain explicit confirmation before writing or updating it.

## 5. Whole-book and volume planning

Use `layered-novel-planning.md` as the single canonical long-novel planning reference.

Confirm:

- whole-book spine;
- major volume sequence;
- protagonist growth line;
- final-stage target;
- stable prohibitions.

Then detail only the current volume and current story arc enough to support chapter contracts.

## 6. System Bible

Use `system-bible-workflow.md` for stable story facts and rules.

The System Bible references Project Profile rather than duplicating its full style/element content. It does not store current injuries, locations, knowledge, possessions, active promises, or other dynamic state.

## 7. Story Memory

For a persistent or continuity-heavy project, use `long-form-continuity.md` and `assets/story-memory.template.md` to create the minimum initial dynamic state.

At project start this may be sparse. Record only active information already established by the approved setup. Do not invent state merely to fill the template.

## 8. Chapter / scene delivery

Use:

- `chapter-pipeline.md`;
- `role-execution-protocol.md`;
- `run-state-protocol.md`;
- `long-form-continuity.md`.

Create the current brief and Context Manifest, apply the current-unit confirmation gate, then execute the seven stages.

## Existing projects

Do not force a complete rebuild.

1. identify existing authoritative files;
2. draft a Project Profile only when missing or clearly inconsistent, then confirm it;
3. retain valid stable canon;
4. bootstrap minimal Story Memory from current/open information under `long-form-continuity.md`;
5. continue from the current volume/arc and next work-unit Preflight.

Do not backfill every historical chapter before useful work can resume.

## Boundary

Startup completes when the project has enough approved foundation for the first current work-unit Preflight. Completion of startup does not authorize automatic chapter generation beyond the applicable confirmation rules.
