# System Bible Workflow — 稳定故事事实与世界规则

Use this reference after the premise, Project Profile, and whole-book spine are approved.

## Ownership

The System Bible is the sole owner of stable story facts:

- core character foundations;
- durable relationships and hidden relationships;
- world, magic, technology, institutional, legal, social, or genre-system rules;
- stable factions, locations, artifacts, identities, and constraints;
- durable canon facts that later prose must not contradict.

It answers:

> What is durably true in this story world?

Do not use it as the live current-state ledger. Current injuries, locations, possessions, knowledge, active promises, foreshadowing progress, and open consequences belong in Story Memory under `long-form-continuity.md`.

Do not duplicate the full style, element, Tone Lock, reader-promise, or Style-Anchor content from Project Profile. Reference the approved Project Profile path and include only a compact identifier when needed.

## Character foundations versus current state

System Bible stores durable characteristics such as background, core motivation, baseline voice, permanent capability rules, and protected secrets.

Story Memory stores changing facts such as current location, injury, inventory, relationship phase, active goal, known information, false belief, and unresolved consequence.

When a temporary condition becomes a durable canon rule, list it as a Stable Canon Candidate in the chapter/periodic audit and obtain explicit confirmation before changing the System Bible.

## Rule precision

For every important rule, state:

- what the rule permits;
- what it forbids;
- its cost or limit;
- who knows it;
- whether exceptions exist;
- what evidence established it.

Avoid vague rules that can be rewritten whenever the plot needs convenience.

## Confirmation

Show the System Bible draft and obtain explicit confirmation before using it as stable canon.

Material changes to identity, world rules, power limits, fixed relationships, protected secrets, or durable canon require renewed confirmation. A chapter run may propose such a change but cannot apply it automatically.

## Audit rule

Lore & Continuity Audit compares candidate facts against:

1. approved System Bible for stable canon;
2. Story Memory for current dynamic state;
3. promoted chapters for source evidence;
4. approved chapter contract for current obligations.

Unsupported or contradicted major facts are blocking. When sources disagree, block Preflight or review rather than silently choosing the most convenient version.
